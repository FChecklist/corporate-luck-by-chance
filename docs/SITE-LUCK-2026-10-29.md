## 8. Open gaps (what I did not do, and why)

1. **The free demo game for 10 people does not exist in this code** (section 4). Five places still promise it.
2. **The builder could not be run here.** `tools/site-brand/build_pages.py` reads the kit from `C:\ct\test-sites\...`, which is not in the cloud. Every change was made twice, in the generator and in the page, with the same text. Please run `build_pages.py` and `write_edge_shell.py` on the local machine once and check that `git diff` shows nothing.
3. **Look compared with Tambola's live site: not done** (section 5). The kit's pinned checksums are the only link.
4. **Console pages** keep their own brand bar and light mode. They have no six-item header (an existing test pins "only the head"). If the owner wants the website header on `zc`/`host` too, that changes their markup and needs a decision.
5. **The console and its mails still say "private"** ("Your private link", "Keep it private" in the Host mails). They are for organizers and Hosts, not players, and the rule is to leave the console as it is. The script lists this as a note.
6. **Console options and the Guide:** the console still offers a 6, 10 or 15 second window and 1 to 20 rounds, and the Guide describes them. The decision "10 only" is not built yet (`docs/boss/OPTIONS_TABLES.md`).
7. **Erasure time:** the draft rules in `docs/boss/RULES_luckbychance.md` say personal details are deleted within 20 hours. The site, the Terms and the code say 24 hours (23 hours in practice). One of them has to change.
8. **The footer sentence about Razorpay** differs from the kit's text. The sister sites keep the old sentence until their builders get the same line.
9. **41 older files** (`app.css`, `z.css`, `guide.js` ...) have no `?v=`. The built `_headers` make css and js `no-cache`, so a changed file is fetched again. Not changed.
10. **"Coming soon" switch (`SITE_HIDDEN`, new on `master`).** When it is on, the front pages answer with a small plain page of their own, not in the brand look. It is off by default and was not touched here. The verifier and the screenshots assume it is off.
11. **The pull request keeps conflicting while `master` moves.** Each merge needs the same care (rebuilt pages against `master`'s new words). Merge it soon, or merge it as the last change before the next version.
12. **No version number was raised.** This branch does not touch `version.json`, the CHANGELOG or the numbering (instruction for this round). `master` now has a rule that every change that goes live raises the number and is recorded with its pull request. When this is merged, the next version, its CHANGELOG entry and the pull request number have to be added by whoever merges it.
13. **The old `site/` folder** (a "coming soon" site, never deployed) is only kept in step for the four legal pages.
