# QA report: Corporate Luck by Chance, live commit 752ff60 (29 October 2026)

Plain English. Written for the owner, the boss session and the session that ports Tambola's hardening (branch luck/rel-after-tambola-2026-10-29). All line numbers are of the live commit 752ff60 unless a commit id is named. Nothing was merged, deployed or sent anywhere; no Cloudflare, Resend or Razorpay call was made; no secret is in any file.

## Five lines

1. The game maths is sound (dice and target are fair, the clock has no gaps, rankings never tie). The problems are around it: money, prizes, results for small games, and words.
2. Found 22 defects with the model on the live commit; 4 are fixed (the other 18 are listed below with the decision they wait for). The three reviews added 131 more rows. The worst: an unpaid game could be played free, a paid game could be cancelled for credit after play, and a long prize list silently started a default game.
3. 9 fix commits, each with a test that fails before and passes after (the word clean-up and the date tests are in the list). Tests went from 1247 pass / 4 fail to 1258 pass / 1 fail; the 1 fail is the boss notes in docs/boss (see D14).
4. Pressing the dice changes nothing (the dice rolls for everybody anyway). The owner draft says no press means no points. That is decision D1 and it decides most of the rest.
5. Money holes in the shared platform (credit in another currency, a bigger limit after the order, account pre-claim, a flood of tiny requests, polling cost) are not Luck only: ask the boss to fix them once for every game.

### 4.2 The model: `tools/qa-model.mjs`

Run from the repository root: `bun tools/qa-model.mjs` (about 15 s; `--quick` for 5 s; `--json` for a machine list). It changes nothing and needs no network. It uses the real game engine (`packages/luck/src`) and the real Worker (`apps/edge/src`) on an in-memory SQLite, the same way the tests do.

What it enumerates (this game has one dice game, no wheel, no draw types, no weights and no turn order; every player plays at the same moment; "segments" are the six dice faces):

| Block | Combinations |
|---|---|
| A fair randomness | 36,000 targets and dice: every face 1 to 6, shares sum to 1, chi-square, target x dice independence, hit chance for each target, mean points per dice round |
| B settings | 20 values for rounds, 13 for the window, prize counts 0 to 6, text 120/121, wrong types, 25 money-like gift words |
| C the clock | window 6/10/15 s x rounds 1, 2, 3, 10, 20: 8,640 checks (every boundary, break, beacon due time, game length) |
| D whole games | 9 player counts (2 to 60) x 3 round counts x 4 seeds = 108 games, 576 rankings, 1,670 tie lines; prize assignment with and without "one win" |
| E real Worker | routes, quorum for 2/3/4/5/6/10/30 players x 4 voter counts, no-result closing and the deletion clock, nicknames, duplicate names, console prizes, round winners, free-game grid (cap 10/11/100/101 x switch on/off), roles, unpaid Start, draft limit |
| F rules draft | each message of RULES_luckbychance.md section 10 against the live pages |

Result on the live commit 752ff60: **22 defects** (FAIL 3, NO_RESULT 1, NOT_LOGICAL 4, INCOMPLETE 5, GAP 9), 8 checks passed. Result on this branch: **18 defects** (FAIL 1, NO_RESULT 1, NOT_LOGICAL 2, INCOMPLETE 5, GAP 9), 11 checks passed. Everything not fixed waits for a decision (section 3) or for the port.

Sound (no defect): dice and target uniform on 1 to 6 and independent (chi-square 7.8 and 3.7 against a limit of 20.5); a hit is 1 in 6 for every target; every face can win; the clock tiles the game with no gap or overlap, a default game is 24 min 40 s; rankings are strict, sorted, have min(10, players) places, totals add up, tie lines are well formed; a game that closes without a result still has its nicknames, votes and participants erased at the deletion time; only the Organizer or a Host can start (stranger, wrong key, player and the AI helper get 403); one dice round for 10,000 players takes 34 ms here (about 0.3 to 1 s on a phone), well inside the 13 s dice round.

## 10. Risks and traps found

- A first reading of the draft-limit counting as a bug was wrong: clone.test.ts says the count is intended. It is now a question (D10), not a defect.
- Rebuilding `apps/web/public/luck-engine.js` with another bun renames every variable (a 15 KB one-line diff). I reverted it. Rebuild once, in the port, after all sources are final.
- Editing `zc.js` with a text tool that changes line endings made a 3,200-line diff (the file has CRLF). I redid it keeping CRLF. Use binary-safe replacements.
- `FORBIDDEN_PRIZE`-style checks and the R43 test scan luck.ts for the words payment, checkout, razorpay, amount: a new Start message must not use them (my first try did and broke two tests).
- The model's own scan for "lease" matched "please" once; fixed.
- The real-Chrome waiting loop that used `pgrep -f` matched itself and never ended; killed.
- Stale cached phone code (`zsw.js` saves pages) can make two phones compute different `line` texts for the same tie, so the votes split (C6c).

## 11. Facts worth keeping

- Default game: 10 rounds x 10 dice rounds, 10 s window, 3 s reveal, 20 s break, 24 min 40 s in all. A hit is 1 in 6; the expected score is 7/12 point per dice round (58.3 per 100).
- Quorum: 2 players need 2, 3 need 3, 4 to 60 need 3, 100 need 5, 1,000 need 50. The game closes with no result 10 minutes after the last dice round if no group reaches it.
- Start needs at least 2 players; seats are frozen at Start; the host page sends the same gift list for every round.
- Paid-lock: 45 s before the scheduled start (worker.ts:214), only for people who are not Organizer or Host.
- Exact new wording: Start unpaid: "This game is not paid for yet. Please pay first, then press Start." Unreadable settings: "Your settings are too long or damaged, so nothing was started. Please shorten the gift texts and press Start again." Cancel after start: "The game has already started, so it cannot be cancelled now. Please use End the game instead."
